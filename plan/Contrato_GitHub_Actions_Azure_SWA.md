# Blueprint: GitHub Actions → Azure Static Web Apps

Documento de referencia para conectar un proyecto Vite/React a Azure Static Web Apps (Free tier) con CI/CD via GitHub Actions y autenticación OIDC.

---

## 1. Prerrequisitos

| Requisito | Detalle |
|---|---|
| Repo GitHub | Público o privado |
| Cuenta Azure | Suscripción activa |
| Azure CLI | `az` instalado localmente (opcional, para setup manual) |
| `gh` CLI | Para verificar secrets y runs desde terminal |
| Node | 22 (leer `.nvmrc`) |

---

## 2. Crear el recurso en Azure Portal

1. Portal → **Static Web Apps** → **+ Create**
2. Campos clave:

| Campo | Valor recomendado |
|---|---|
| Resource group | `rg-<proyecto>` |
| Name | `<proyecto>` |
| Plan | Free |
| Region | East Asia (o el más cercano) |
| Source | GitHub |
| Repository | `<usuario>/<repo>` |
| Branch | `main` |
| Build preset | **Custom** |
| App location | `/` |
| Output location | `build` |

3. Al completar, Azure:
   - Crea el recurso con URL `https://<adjective>-<noun>-<hex>.azurestaticapps.net`
   - Crea el secret `AZURE_STATIC_WEB_APPS_API_TOKEN_<ADJECTIVE>_<NOUN>_<HEX>` en el repo
   - Genera el archivo `.github/workflows/azure-static-web-apps-<adjective>-<noun>-<hex>.yml`

> **Importante:** anota el nombre exacto del secret y del archivo de workflow — ambos contienen el nombre del recurso Azure y no deben cambiarse.

## 3. Restricciones críticas de Azure SWA

### 3.1 El nombre del workflow es fijo

Azure SWA con OIDC verifica que el deploy venga de un workflow con nombre exactamente:

```
azure-static-web-apps-<adjective>-<noun>-<hex>.yml
```

Renombrarlo produce este error:

```
Could not determine the Static Web App from the GitHub OIDC workflow reference.
Ensure the workflow file generated by Azure Static Web Apps has not been renamed.
```

**Regla:** Nunca renombrar el archivo. Agregar pasos propios (test, build) dentro de ese mismo archivo.

### 3.2 El secret tiene sufijo del recurso

Azure crea el secret con el nombre del recurso incluido:

```
AZURE_STATIC_WEB_APPS_API_TOKEN_PURPLE_PEBBLE_07A0DA800   ← correcto
AZURE_STATIC_WEB_APPS_API_TOKEN                            ← incorrecto
```

Verificar el nombre real:

```bash
gh api /repos/<owner>/<repo>/actions/secrets --jq '.secrets[].name'
```

### 3.3 Output directory: `build/`, no `dist/`

El Oryx builder de Azure SWA espera la salida en `build/` (convención de Create React App). Vite por defecto usa `dist/`.

**En `vite.config.ts`:**

```ts
build: {
  outDir: 'build',
}
```

**En el workflow:**

```yaml
output_location: "build"
```

Error sin este cambio:

```
The app build failed to produce artifact folder: 'build'
```

### 3.4 OIDC es obligatorio además del deployment token

El workflow necesita obtener un ID token de GitHub y pasarlo al deploy action. Sin OIDC, el token solo no es suficiente.

## 4. Workflow completo

Archivo: `.github/workflows/azure-static-web-apps-<adjective>-<noun>-<hex>.yml`

```yaml
name: Azure Static Web Apps CI/CD

on:
  push:
    branches:
      - main
  pull_request:
    types: [opened, synchronize, reopened, closed]
    branches:
      - main

jobs:
  build_and_deploy_job:
    if: github.event_name == 'push' || (github.event_name == 'pull_request' && github.event.action != 'closed')
    runs-on: ubuntu-latest
    name: Build and Deploy Job
    permissions:
      id-token: write    # requerido para OIDC
      contents: read

    steps:
      - uses: actions/checkout@v4
        with:
          submodules: true
          lfs: false

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Test
        run: npm run test:run

      - name: Build
        run: npm run build

      # OIDC: Azure verifica identidad del workflow via token firmado por GitHub
      - name: Install OIDC Client from Core Package
        run: npm install @actions/core@1.6.0 @actions/http-client

      - name: Get Id Token
        uses: actions/github-script@v6
        id: idtoken
        with:
          script: |
            const coredemo = require('@actions/core')   # NO usar 'core' — nombre reservado internamente
            return await coredemo.getIDToken()
          result-encoding: string

      - name: Build And Deploy
        id: builddeploy
        uses: Azure/static-web-apps-deploy@v1
        with:
          azure_static_web_apps_api_token: ${{ secrets.AZURE_STATIC_WEB_APPS_API_TOKEN_<SUFFIX> }}
          action: "upload"
          app_location: "/"
          api_location: ""
          output_location: "build"
          github_id_token: ${{ steps.idtoken.outputs.result }}

  close_pull_request_job:
    if: github.event_name == 'pull_request' && github.event.action == 'closed'
    runs-on: ubuntu-latest
    name: Close Pull Request Job
    steps:
      - name: Close Pull Request
        id: closepullrequest
        uses: Azure/static-web-apps-deploy@v1
        with:
          azure_static_web_apps_api_token: ${{ secrets.AZURE_STATIC_WEB_APPS_API_TOKEN_<SUFFIX> }}
          action: "close"
```

> `<SUFFIX>` = parte del nombre del recurso en mayúsculas, ej: `PURPLE_PEBBLE_07A0DA800`

## 5. staticwebapp.config.json

Debe estar en la raíz del repo. Configura el SPA fallback, headers de seguridad y MIME types.

```json
{
  "navigationFallback": {
    "rewrite": "/index.html",
    "exclude": ["/assets/*", "/config.json", "*.{ico,png,svg,webp,jpg,jpeg,gif,woff,woff2}"]
  },
  "mimeTypes": {
    ".json": "application/json"
  },
  "globalHeaders": {
    "X-Content-Type-Options": "nosniff",
    "X-Frame-Options": "DENY",
    "Referrer-Policy": "strict-origin-when-cross-origin",
    "Permissions-Policy": "camera=(), microphone=(), geolocation=()"
  },
  "responseOverrides": {
    "404": { "rewrite": "/index.html", "statusCode": 200 }
  }
}
```

## 7. Comportamiento del pipeline

| Evento | Resultado |
|---|---|
| `push` a `main` | Build + deploy a producción |
| PR abierto / actualizado contra `main` | Build + deploy a staging (URL temporal) |
| PR cerrado | Limpieza del entorno staging |

Los tests (`npm run test:run`) bloquean el deploy si fallan.

---

## 8. Regenerar el deployment token

Si el token expira o se revoca:

1. Azure Portal → Static Web Apps → recurso → **Manage deployment token**
2. Copiar el nuevo token
3. Actualizar el secret en GitHub:

```bash
gh secret set AZURE_STATIC_WEB_APPS_API_TOKEN_<SUFFIX> \
  --repo <owner>/<repo> \
  --body "$AZURE_STATIC_WEB_APPS_API_TOKEN"
```

## 9. Troubleshooting

### `Could not determine the Static Web App from the GitHub OIDC workflow reference`

El workflow fue renombrado.  
**Fix:** Restaurar el nombre original `azure-static-web-apps-<adjective>-<noun>-<hex>.yml`.

### `No matching Static Web App was found or the api key was invalid`

Nombre del secret incorrecto o falta OIDC.  
**Fix:** Verificar nombre real con `gh api /repos/.../actions/secrets` y que el workflow tenga `permissions: id-token: write` + los pasos OIDC.

### `The app build failed to produce artifact folder: 'build'`

Vite está outputeando a `dist/`.  
**Fix:** `vite.config.ts` → `build: { outDir: 'build' }` y workflow → `output_location: "build"`.

### `deployment_token provided was invalid`

Token incorrecto o de otro recurso.  
**Fix:** Regenerar desde Azure Portal y actualizar el secret.

### `SyntaxError: Identifier 'core' has already been declared`

En `actions/github-script`, `core` es una variable interna reservada.  
**Fix:** Renombrar la variable local a cualquier otro nombre, ej: `coredemo`.

### `skip_app_build: true` no evita que Oryx re-ejecute el build

Este parámetro no tiene efecto si el directorio de salida no existe antes del step de deploy.  
**Fix:** Asegurar que `npm run build` corra antes y genere en `build/`.

## 10. Verificar estado del deploy

```bash
# Últimos 5 runs
gh run list \
  --repo <owner>/<repo> \
  --workflow azure-static-web-apps-<adjective>-<noun>-<hex>.yml \
  --limit 5

# Log de un run específico
gh run view <run-id> --log
```

## 11. Plataformas alternativas

Si Azure no es una opción, la misma app SPA funciona en:

| Plataforma | Comando |
|---|---|
| GitHub Pages | Build → push `build/` a rama `gh-pages` |
| Netlify | Drag & drop `build/` en netlify.com/drop |
| Vercel | `vercel --prod` desde la raíz |
